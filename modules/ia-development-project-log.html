Scope

Unit 11 · In development since 26 August 2026 · Log covers 26 August to 15 September · Evidences learning outcomes 2 and 3

The assignment is on the module page. This log records the individual implementation of the agent Group B designed in Unit 6, in the order the work happened. The code, its versions, the tests and the record of every fault found are kept in a separate private repository, and that material is what this log draws on.

What Is Being Built

Two cooperating agents over a schema-validated JSON buffer, with deduplication, validation and storage deliberately outside the model. The Planning Agent takes a research question and its criteria, breaks it into search subgoals, runs them against PubMed, PubMed Central, Semantic Scholar and Crossref, and decides after each retrieval whether to continue, refine, drop or finish. The Curation Agent takes the papers handed over, screens each against the criteria, ranks them, and asks for a summary with a supporting extract that is then checked against the paper it came from. A human reviewer approves, rejects or flags each record, and only approved records are stored.

Progress Against the Plan

26 August to 1 September: the retrieval layer

Built so far: the requirements table, the shared HTTP layer, four source adapters for PubMed, PubMed Central, Semantic Scholar and Crossref, the record formats both agents exchange, and a hundred abstracts screened by hand to measure recall against. Since 1 September the two agents are connected into a single run, with the hand-over between them covered by integration tests.

2 to 8 September: both agents

The Planning Agent closed its decompose, search, decide and finish loop on 2 September. The Curation Agent followed on 8 September: records combined and shared out at the hand-over, papers screened and put in rank order, every extract checked against the paper it was taken from, and only approved records saved. Work on the reviewer interface started the same day. Of twenty functional requirements, eleven are done and seven part-built. Two have not been started: entering the research question through the interface, and the audit log. Nothing has yet been run end to end, which is what the functional test run is for, and that is next.

14 and 15 September: the tutor’s three points, and the first measurement

I completed the tutor’s three points from the team report on 14 September, the day after receiving the feedback: a class diagram of the records carried through a run, a sequence diagram showing one run and its error paths, and a test plan against the CLEF 2019 systematic review CD011571, with a script to measure performance against it. The sequence diagram also exposed a fault the existing tests had missed: the refusal of a corrupted record at the hand-over reached the screen with nothing to handle it. I fixed it the same day. Nine functional tests were then written and passed. Nothing is now unstarted: eleven of twenty requirements are implemented and nine are in progress. The first dataset run on 15 September gave retrieval recall of 0.67 against the 0.80 criterion. Curation precision was 1.0 for the four papers judged include, while four relevant papers were judged exclude and seven remained uncertain. The next step is to repeat the run from the saved records.
